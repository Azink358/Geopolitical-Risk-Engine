# Macro‑Sentry Geopolitical Risk Engine

**A modular Python engine for staging, validating, and visualizing geopolitical risk data.**

---

## 📖 Overview
Macro‑Sentry is a data pipeline and analytics framework designed to model geopolitical risk impacts on supply chains, energy markets, and maritime routes. It demonstrates recruiter‑ready engineering practices with modular orchestration, schema validation, and reproducible outputs.

The engine ingests raw datasets, transforms them into fact tables, enriches them with dimension builders, and validates everything against a central schema. Outputs are recruiter‑friendly CSVs ready for dashboards, BI tools, or machine learning models.

---

## 🚀 Features
- **Data Engine Orchestration**: Sequential stager execution with schema validation.
- **Dimension Staging**: Country, sector, fuel type, conflict phase, response, and event dimensions aligned with fact tables.
- **Schema‑Driven Design**: Centralized YAML mappings enforce consistency and prevent merge errors.
- **CLI Integration**: Flexible flags (`--all`, `--facts`, `--dims`) for full or partial runs.
- **Resilient Workflow**: Defensive logic handles inconsistent stager outputs (`None`, `TextFileReader`) without breaking downstream merges.
- **Logging**: Transparent INFO logs track progress, row counts, and validation status.

---

## 📂 Project Structure
- **app/** → Streamlit or app interface  
- **data/**  
  - **raw/** → Source CSVs (e.g., supply chain, energy volatility, maritime costs)  
  - **processed/** → Fact and dimension tables generated by pipeline  
  - **features/** → Feature‑engineered datasets  
  - **reference/** → Lookup tables (countries, sectors, fuel types, routes, etc.)  
- **notebooks/** → Exploratory analysis and prototyping  
- **src/**  
  - **database/** → DB manager and SQL playground  
  - **models/** → Risk predictor models  
  - **processing/** → Stagers, feature engineering, data engine  
  - **validation/** → Schema validation utilities  
- **main.py** → CLI entrypoint  
- **schema.yaml / schema_mappings.yaml** → Schema definitions and mappings  
- **requirements.txt** → Dependencies
